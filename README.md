# University Portal Honeypot — هاني بوت بوابة جامعية

هاني بوت ويب تفاعلي يحاكي بوابة خدمات الطلبة بواجهات مطابقة، مدعوم بقاعدة بيانات
طُعم ضخمة، طبقة حماية على مستوى المنظومة، ولوحة رصد (SOC) تلتقط **بصمة كاملة عن جهاز
كل من يدخل** على المصيدة. الهدف: جذب المهاجمين إلى نظام طُعم معزول وتسجيل وتصنيف كل
محاولة + استخبارات عن أجهزتهم — لإخراج تقرير دفاعي.

> ⚠️ **مشروع دفاعي/تعليمي.** الواجهات تحاكي شكل بوابة حقيقية لأغراض المحاكاة، لكنها
> **غير متصلة بأي نظام حقيقي ولا تحوي أي بيانات حقيقية** — كل الطلاب والعلامات والمالية
> مفبركة (`app/decoy_db.py`)، والبيانات الشخصية التي كانت بالواجهات الملتقطة **تمت
> إزالتها بالكامل** واستُبدلت بقالب محايد. شغّله في بيئة معزولة فقط.

---

## ما الذي يقدّمه

- **بوابة ديناميكية مطابقة** — تسجيل دخول + ~39 صفحة (علامات، مالية، جدول، خطة، ملف
  الطالب...). كل طالب يفوت يشوف **بياناته هو** مولّدة حيّاً من قاعدة البيانات.
- **قاعدة بيانات طُعم ضخمة** — ~15 ألف طالب، 346 ألف علامة، مالية، حسابات موظفين،
  مكتبة، رسائل... (~570 ألف صف). الدخول قابل للحقن عمداً (SQLi) كطُعم — لكن الاتصال
  **للقراءة فقط** فلا يقدر أي حقن يعدّل القاعدة.
- **مصادقة ASP.NET WebForms محاكاة** — `__VIEWSTATE`/`__EVENTVALIDATION`، كوكي
  `ASP.NET_SessionId`، وترويسات IIS — فالطلبات الآلية التي تتخطى النموذج تُرفض
  وتُرصد (`/error.aspx`).
- **طبقة حماية للمنظومة** (`app/security.py`) — راجع الأسفل.
- **لوحة رصد SOC + بصمة الأجهزة** (`/_monitor`) — راجع الأسفل.

## التشغيل

```powershell
cd university-honeypot
python -m venv .venv ; .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m app.honeypot
```

- البوابة (واجهة المهاجم): http://127.0.0.1:8080/
- لوحة الرصد المحمية: http://127.0.0.1:8080/_monitor

سيرفر التطوير يخدم **HTTP** افتراضياً. تشغيل HTTPS اختياري: `HONEYPOT_TLS=1` (تُولَّد
شهادة self-signed صالحة للمتصفحات في `certs/` تلقائياً)، أو مرّر شهادتك عبر
`HONEYPOT_SSL_CERT` / `HONEYPOT_SSL_KEY`.

أو عبر Docker (معزول): `docker compose up --build`

تجربة سريعة كطالب: أي حساب من القاعدة، مثلاً عبر حقن `' OR '1'='1' -- ` في خانة الدخول.

## لوحة الرصد + بصمة الجهاز (`/_monitor`)

محمية بـ **HTTP Basic auth**. بيانات الدخول الافتراضية:

```
user: mahde
pass: 123qweQWE@
```

كلمة المرور مخزّنة كـ **hash (PBKDF2)** فقط — هذا الملف آمن للنشر. بعد 5 محاولات
فاشلة من نفس الـIP يصير قفل 5 دقائق.

عند تحميل أي صفحة طُعم، سكربت (`app/intel.py`) يجمع من متصفح الزائر ويرسله لـ`/_collect`:
نظام التشغيل/المتصفح/المحرّك، كرت الشاشة (WebGL/GPU)، دقة الشاشة ونسبة البكسل،
**المنطقة الزمنية واللغة** (مؤشّر موقع بدون أي إذن)، عدد الأنوية والذاكرة، نوع الشبكة
والبطارية، بصمة Canvas والخطوط، **عناوين IP المحلية عبر WebRTC** (تكشف العنوان خلف
VPN/NAT)، علامات الأتمتة (`webdriver`/headless → **كشف بوت**)، و(اختياري) **GPS** إن
مُنح الإذن. اللوحة تعرض كل هذا لكل IP مع تغذية حيّة، رسوم، بحث، وتصدير JSON.

فوق التغذية الخام، اللوحة تشتقّ ما يهمّ محلّل الـSOC فعلاً:

- **درجة تهديد (0–100) لكل مهاجم** مع شرح العوامل — وزن خطورة الهجمات، عدد التقنيات
  عالية الخطورة، أدوات/أتمتة، اتّساع الاستطلاع، تلاعب `__VIEWSTATE`، وتدوير الـIP.
  الجدول يُرتَّب حسب التهديد ويلوّن الصفوف الحرجة.
- **ربط الفاعلين عبر العناوين** — نفس بصمة الجهاز (`fpId`) من أكثر من IP = مُشغّل واحد
  يدوّر عبر VPN/بروكسي. يظهر كشارة 🔗 وبطاقة ربط مستقلّة.
- **سلسلة الهجوم (kill-chain)** — اضغط أي صف فتُعاد بناء تسلسل كل ما فعله ذلك الـIP
  زمنياً (استطلاع ← طُعم ← محاولات دخول ← حقن)، جاهز للتقرير.
- **تحكّم بالتغذية** — «الهجمات فقط»، إيقاف/استئناف التحديث، وتنبيه (وميض + صوت) عند
  وصول هجوم جديد. تصدير **JSON** و**CSV** (`/_monitor/api/export.csv`) للتقرير.

> هذه استطلاع سلبي لمن يتفاعل مع المصيدة (بيانات يكشفها المتصفح نفسه) — لأغراض
> الاستخبارات الدفاعية فقط.

## ربط Suricata (IDS على طبقة الشبكة)

كل تنبيه من `eve.json` يُحوّل لحدث بنفس شكل أحداث المصيدة ويُكتب بنفس
السجل. ولأن الاثنين يتمحورون حول `src_ip`، اللوحة تدمجهم تلقائياً تحت مهاجم
واحد: ما رآه السينسور على السلك وما رآه التطبيق، بدرجة تهديد واحدة.

```powershell
python -m app.ids --stats  eve.json     # ماذا يحوي الملف وماذا سيُستبعد
python -m app.ids --import eve.json     # استيراد لقطة سابقة (يحفظ وقت كل تنبيه)
python -m app.ids --tail   eve.json     # متابعة حيّة
```

| المتغيّر | الوظيفة |
|---------|---------|
| `SURICATA_EVE` | مسار `eve.json` — يشغّل المتابعة الحيّة داخل التطبيق |
| `SURICATA_HOME_NET` | عناوين/شبكات المصيدة نفسها — تُستبعد تنبيهاتها الصادرة |
| `SURICATA_INGEST_ALL` | `1` لإدخال حتى الترافيك الصادر من المصيدة (ضجيج) |
| `SURICATA_MIN_SEV` | أقصى رقم خطورة يُقبل (1 = الأشد، الافتراضي 3) |

**مهم:** اضبط `SURICATA_HOME_NET` دائماً. السينسور يسجّل جهازه أيضاً، و`apt update`
يُطلق `ET INFO GNU/Linux APT User-Agent Outbound`، فبدون الفلترة يظهر جهازك كأخطر مهاجم.
التنبيهات المعلوماتية (severity 3) تأخذ وزناً مخفّضاً بدرجة التهديد حتى لا يرفعها الحجم وحده،
واجتماع كشف شبكي مع كشف تطبيقي لنفس العنوان يرفعها (تأكيد مزدوج).

الملف يحتفظ بموقع القراءة في `logs/.suricata_offset.json`، فإعادة الاستيراد لا تكرّر الأحداث.

## تنبيهات تليجرام

`app/notify.py` يشترك في **تيار أحداث المشروع نفسه** لا في سجل سوريكاتا لوحده، فمسار
إنذار واحد يغطّي الطبقتين: هجمات التطبيق من `detectors.py` وتنبيهات الشبكة من `ids.py`.

```powershell
python -m app.notify --test      # تنبيه اختباري لكل المستلمين
python -m app.notify --report    # تقرير فوري مع ملف CSV
python -m app.notify --discover  # من راسل البوت مؤخراً (لإضافة مستلم جديد)
python -m app.notify --whoami    # هوية البوت والمستلمون المضبوطون
```

**لإضافة زميل للتنبيهات:** يفتح البوت ويبعث `/start`، ثم شغّل `--discover` وأضف
الـid الظاهر إلى `TELEGRAM_CHAT_IDS`. كل مستلم يصله كل تنبيه وكل تقرير،
وفشل مستلم واحد (حظر البوت مثلاً) لا يمنع الباقين.

**ثلاث طبقات للزناد**، لأن أرضية خطورة واحدة لا تكفي: خطورة الحدث المفرد، زائد تقنيات
تُنبّه دائماً (المسح الآلي)، زائد **تصعيد** ينطلق لما تدخل درجة المصدر التراكمية فئة
أعلى حتى لو ما كان فيه طلب واحد خطير. الطبقة الثالثة هي اللي تمسك المسح البطيء.
حالة المحرّك معروضة على `/_monitor/api/notify` للتشخيص.

الرسائل بالإنجليزية بصيغة SOC: شريط خطورة مرئي، درجة التهديد الحالية للمصدر،
البيانات المُدخلة، الـSQL المنفّذ على الطُعم، وسمعة العنوان من AbuseIPDB.

يبدأ تلقائياً مع التطبيق.

### أين تُحفظ الأسرار

`app/config.py` يحلّ كل إعداد بهذا الترتيب:

1. متغيّر البيئة الفعلي `NAME`
2. ملف سرّ `NAME_FILE=/run/secrets/x` (نمط Docker / Kubernetes)
3. ملف `.env` في جذر المشروع — مخفي ومتجاهل من git
4. القيمة الافتراضية

للبدء: `cp .env.example .env` ثم املأ القيم. ملف `.env.example` **مرفوع عمداً**
ليوثّق المفاتيح المطلوبة، ولا يحوي أي سرّ حقيقي.

على أي سيرفر: متغيّرات البيئة تتغلّب على `.env`، فـRender وDocker يمرّرون أسرارهم
من مخزنهم الخاص وما بتحتاج ترفع `.env` أصلاً. وفي `render.yaml` معرّفة بـ`sync: false`
يعني Render يسألك عنها ويخزّنها عنده.

حدّ واضح يستحق الذكر: أي سرّ يقدر التطبيق يقرأه وقت التشغيل، يقدر يقرأه من
عنده وصول shell على نفس الجهاز. هذا الترتيب يحميك من مسارات التسرّب الواقعية
(git push، ضغط المجلد، لقطة شاشة للكود)، لا ممّن يملك السيرفر أصلاً.

| المتغيّر | الوظيفة | الافتراضي |
|---------|---------|-----------|
| `TELEGRAM_TOKEN` | توكن البوت من @BotFather | مطلوب |
| `TELEGRAM_CHAT_ID` / `TELEGRAM_CHAT_IDS` | المستلمون (قائمة بفواصل، المفتاحان يُدمجان) | مطلوب |
| `ABUSEIPDB_KEY` | إثراء سمعة الـIP (مخزّن مؤقتاً 6 ساعات) | — |
| `TELEGRAM_MIN_SEVERITY` | أرضية التنبيه: low/medium/high | `high` |
| `TELEGRAM_COOLDOWN` | ثوانٍ قبل تكرار نفس (IP، تقنية) | `600` |
| `TELEGRAM_REPORT_EVERY` | دقائق بين التقارير، 0 = إيقاف | `360` |
| `TELEGRAM_QUIET_IDS` | لا تنبّه على تنبيهات IDS المعلوماتية | `1` |
| `TELEGRAM_ALERT_CATEGORIES` | تقنيات تُنبّه دائماً مهما كانت الأرضية | `scanner` |
| `TELEGRAM_ESCALATE_FROM` | ينبّه لما ترتفع درجة المصدر لفئة أعلى | `medium` |

قرارات تصميم تستحق الذكر:

- **لا شيء يعطّل مسار الطلب.** الأحداث تُرمى على طابور محدود وخيط عامل يتولّى الشبكة.
- **HTML لا Markdown.** توقيعات سوريكاتا مليانة `_` والحمولات فيها `<` و`` ` ``،
  وMarkdown يردّ 400 فيضيع التنبيه بصمت. كل قيمة تمرّ على `html.escape`.
- **تهدئة وتجميع.** تشغيل sqlmap واحد = آلاف الأحداث؛ المتكرر يُطوى في ملخّص واحد.
- **احترام 429.** يقرأ `retry_after` من تليجرام ويعيد المحاولة بدل إسقاط الرسالة.

## الإعداد والتحصين (متغيّرات البيئة)

| المتغيّر | الوظيفة | الافتراضي |
|---------|---------|-----------|
| `MONITOR_USER` / `MONITOR_PASS` | بيانات لوحة الرصد | `mahde` / (hash لـ`123qweQWE@`) |
| `MONITOR_PASS_HASH` | بدل كلمة المرور بـhash جاهز | — |
| `MONITOR_ALLOW_IPS` | IPs تتخطى المصادقة (مثلاً `127.0.0.1`) | فارغ = المصادقة دائماً |
| `HONEYPOT_SECRET` | مفتاح توقيع توكنات VIEWSTATE | عشوائي لكل تشغيل |
| `HONEYPOT_MAX_BODY` | حدّ حجم الطلب (DoS) | 262144 بايت |
| `HONEYPOT_RATE` / `HONEYPOT_RATE_WINDOW` | مانع الإغراق لكل IP | 240 / 10s |
| `HONEYPOT_HTTPS` | فعّله خلف TLS خارجي/بروكسي (يضيف Secure للكوكي + HSTS) | — |
| `HONEYPOT_TLS` | يشغّل HTTPS على سيرفر التطوير (شهادة self-signed) | — (HTTP) |
| `HONEYPOT_SSL_CERT` / `HONEYPOT_SSL_KEY` | شهادة/مفتاح TLS جاهزين (يشغّلان HTTPS) | — |

التحصينات المطبّقة: مصادقة + قفل تخمين على لوحة الرصد، مانع إغراق لكل IP، حدّ لحجم
الطلب، اتصال قاعدة بيانات للقراءة فقط، كوكي `HttpOnly`+`SameSite`, ترويسات أمان
كاملة، معالجات أخطاء لا تسرّب أي stack trace، وحدّ لذاكرة الجلسات.

> **استبدل `MONITOR_PASS` و`HONEYPOT_SECRET` قبل أي نشر فعلي.**

## الاستضافة على GitHub — مهم

GitHub يستضيف **الكود** (المستودع) ممتاز. لكن **GitHub Pages يخدم ملفات ثابتة فقط
ولا يشغّل Python/Flask** — يعني الهاني بوت **لن يعمل** عليه. لتشغيله فعلياً تحتاج
مستضيفاً يشغّل Python:

- **Render / Railway / PythonAnywhere / Fly.io** (مجاني/سهل لتطبيقات Flask)، أو
- **VPS أو Docker** على سيرفر تتحكم به.

وفي كل الأحوال: شغّله **معزولاً (مختبر/VM)**، ولا تنشر النسخة بشعار وقالب الجامعة على
دومين عام أو شبيه باسم الجامعة — لأن نسخة طبق الأصل لصفحة دخول مؤسسة حقيقية على
الإنترنت = صفحة تصيّد (phishing)، وهذا ممنوع. استخدمه لأغراض البحث الدفاعي فقط.

## خريطة الملفات

| الملف | الدور |
|------|------|
| `app/honeypot.py` | تطبيق Flask، المسارات، المصادقة، حقن البصمة، التقاط كل طلب |
| `app/security.py` | المصادقة، مانع الإغراق، حدود الطلب، الإعداد من البيئة |
| `app/intel.py` | سكربت بصمة جهاز الزائر (يُحقن بكل صفحة) |
| `app/dashboard.py` | تجميع الاستخبارات + لوحة `/_monitor` + APIs |
| `app/decoy_db.py` | مولّد قاعدة الطُعم الضخمة + الاستعلامات القابلة للحقن (read-only) |
| `app/dyn.py` | توليد الجداول الديناميكية (علامات/مالية/مساقات) لكل طالب |
| `app/detectors.py` | تصنيف الهجمات (SQLi/XSS/LFI/CMDi/SSTI/scanners) |
| `app/logger.py` | تسجيل كل حدث JSON في `logs/events.jsonl` |
| `app/portal/` | الصفحات المطابقة (منظّفة من البيانات الحقيقية) |
| `app/templates/` | الدخول، الخطأ، ولوحة الرصد |

`logs/` و`decoy.sqlite` متجاهلة بالـ`.gitignore` (تُولّد عند التشغيل وتحوي بيانات
الزوار) فلا تُرفع.
